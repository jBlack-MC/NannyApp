Automated verification, signed Android releases, GitHub distribution and website delivery.

Every change is checked by GitHub Actions. A release is deliberately created from a version tag so the source, APK and release notes are traceable.

3. Required repository configuration

  • NANNYAPP_RELEASE_KEYSTORE_BASE64
  • NANNYAPP_RELEASE_KEYSTORE_PASSWORD
  • NANNYAPP_RELEASE_KEY_ALIAS
  • NANNYAPP_RELEASE_KEY_PASSWORD

Set the repository variable NANNYAPP_RELEASE_API_URL to the HTTPS API ending in /api/. Secrets and the signing keystore are never committed.

4. Release procedure

  1. Run the CI workflow and confirm the Android tests, lint and release compilation pass.
  2. Create and push an annotated version tag, for example v1.0.2.
  3. GitHub Actions builds, signs and verifies the APK, then attaches it to the GitHub Release.
  4. Set NANNYAPP_APK_URL on the web host to the stable latest-release URL.
  5. Open the website download page and install the APK on a real Android phone.
  6. Record the release tag, APK SHA-256, device test result and rollback version.

5. Quality and rollback gates

Before release

All automated checks pass, API is HTTPS, database migrations are applied, and the APK signature verifies.

Real device

Install on Android 8+, register, verify email, log in, change settings, exercise core features and capture evidence.

Web distribution

The download endpoint redirects to the GitHub release asset and never exposes the signing key or source secrets.

Rollback

Keep the prior GitHub release and APK URL available. Re-point the website to the previous tag if a release is withdrawn.
